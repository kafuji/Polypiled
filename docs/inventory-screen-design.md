# インベントリ画面の刷新（検討）

2026-11-18。検討段階。実装はまだない。

左に装備部位、右に持ち物のグリッドという、よくある形のインベントリ画面を作る。
この画面だけで、持ち物の整理・装備の付け外し・コンテナの出し入れを同じ操作感でできるようにする。

方針は **「中身は NetHack のまま、手触りはゲーマーになじみのある形」**。
画面は NetHack のコマンドを組み立てて送るだけで、可否の判定・かかるターン・メッセージ・失敗（呪い・爆発）はすべて本体が決める。
画面が独自にルールを持つと、本体とずれたときに嘘をつくことになるので持たない。

## 1. 画面の構成

```
┌──────────────────────────────────────────────────────────────────┐
│ 持ち物                                    ⚖ 412 / 450  ▮▮▮▮▮▮▮▯ 余裕 38 │
├────────────────────┬─────────────────────────────────────────────┤
│  [兜]              │  a  b  c  d  e  f  g  h  i  j  k  l  m      │
│ [首][外套]         │  n  o  p  q  r  s  t  u  v  w  x  y  z      │
│ [手][鎧 ][盾]      │  A  B  C  D  E  F  G  H  I  J  K  L  M      │
│     [肌着]         │  N  O  P  Q  R  S  T  U  V  W  X  Y  Z      │
│ [指L][靴][指R]     │  $                                          │
│ [武器][予備][矢筒] │──────────────────────────────────────────── │
│ [目隠し]           │  ▼ 開いているコンテナ: 袋 (p)               │
│                    │  [□][□][□][□] …                             │
│                    │──────────────────────────────────────────── │
│                    │  ▼ 足元: 箱、短剣 ×3、…                     │
└────────────────────┴─────────────────────────────────────────────┘
```

| 区画 | 内容 |
| --- | --- |
| 装備部位（左） | `W_ARMH`, `W_AMUL`, `W_ARMC`, `W_ARMG`, `W_ARM`, `W_ARMS`, `W_ARMU`, `W_RINGL`, `W_ARMF`, `W_RINGR`, `W_WEP`, `W_SWAPWEP`, `W_QUIVER`, `W_TOOL`。主人公の立ち絵を背景に置き、部位を体の位置に並べる。二刀流中は「予備」を「左手」と表示する。鉄球と鎖（`W_BALL`/`W_CHAIN`）は外せない枠として出す |
| 持ち物（右上） | 52 マスの固定グリッド。**マスの位置 = 持ち物の文字**（a〜z、A〜Z）。金貨は `$` の専用マス |
| コンテナ（右中） | 開いているコンテナの中身。5 章 |
| 足元（右下） | 主人公のいるマスの物と、床のコンテナ。拾う・置く・床の箱を開ける |
| 重量（上端） | 4 章 |

グリッドの位置を持ち物の文字に一致させるのがこの設計の要。
NetHack の持ち物の順序はもともと文字そのもので（`#adjust` で並べ替える）、ゲーマーの「スロットに物を置く」感覚とそのまま重なる。
並べ替えのための独自の状態を持たないので、セーブ・再開・別の画面（従来のメニュー）と食い違わない。

## 2. アイテムの表示

アイコン主体。1 マスに 1 つのタイル（見た目のタイル。K3 の規則どおり、未識別の物は見た目でしか出さない）。

| 情報 | 表し方 | 出す条件（本体の知識） |
| --- | --- | --- |
| 数量 | 右下の数字 | 常に |
| 祝福 | 淡い金の後光（外周のにじみ）＋左上に小さな印 | `bknown` かつ `blessed` |
| 呪い | 暗い紫のもや・ゆっくり脈打つ縁 | `bknown` かつ `cursed` |
| 呪われていない | 印なし（または設定で細い白線） | `bknown` で祝福・呪いなし |
| BUC 不明 | 何もつけない。設定で「?」の小印 | `!bknown` |
| 錆・腐食 | タイルに錆色／緑青のノイズを重ねる。段階（1〜3）で濃さを変える | `oeroded`（`doname` と同じく見た目で分かる） |
| 焦げ・朽ち | 焦げ色の縁取り／ひび | `oeroded2` |
| 防錆など | 小さな盾の印 | `rknown` かつ `oerodeproof` |
| 強化値・充填数 | 左下に `+2`, `(0:4)` | `known` |
| 装備中 | 部位パネル側に置き、グリッド側は半透明の「影」と部位アイコン | `owornmask` |
| 未払い | 値札の印、ツールチップに値段 | `unpaid` |
| 光っている | 灯りの粒子 | `lamplit` |
| 名付け（call / name） | 小さな筆の印 | 名前がある |

マウスオーバー（パッドではフォーカス、タッチでは長押し）でツールチップ:
`doname` の名前（日本語化済み）、文字、重量（4 章の規則で）、可能な操作の一覧と、それぞれの所要ターン（分かる場合）。
既存の `WikiLinkedText` はツールチップ内でも使える。

エフェクトは色だけに頼らない（色覚の差・ASCII モード）。どの状態にも形の違う小印を併用し、設定で「印だけ」に切り替えられる。
`inventoryReducedMotion` が有効なら脈動や粒子は止める。

## 3. 操作

### 3.1 基本の対応

| 操作 | NetHack のコマンド | ターン |
| --- | --- | --- |
| グリッドから部位へドラッグ | 防具 `W`、装飾品 `P`、武器 `w`、予備 `x` 経由、矢筒 `Q`、目隠し等 `P` | 防具は `oc_delay`、ほかは 1 |
| 部位からグリッドへドラッグ | `T` / `R` / `w-`（素手）/ `Q` の解除 | 防具は `oc_delay`、ほかは 1 |
| 装備中の部位に別の物を重ねる | 外す → 着る の 2 コマンド（外套の下の鎧などは 3 以上） | 合計を表示 |
| グリッド内で移動 | `#adjust`（空きマスなら文字の付け替え、物があれば入れ替え） | 0 |
| 同じ物の上へ移動 | `#adjust` で合流（本体がまとめられる物だけ） | 0 |
| Shift＋ドラッグ | `#adjust` で数量を指定して分割 | 0 |
| ダブルクリック | その物の既定の操作（防具なら着る、薬なら飲む…）。既定値は設定で選べる | 操作による |
| 右クリック | 既存の `InventoryContextMenu` | 操作による |
| 足元へドラッグ | `d`（数量つきは既存の `InventoryDropCountDialog`） | 1 |
| 足元からグリッドへ | `,` で選んで拾う | 1 |
| コンテナへ／から | 5 章 | 5 章 |

### 3.2 時間を使う操作の扱い

ゲーマー向けの画面で一番ずれやすいのが「インベントリを開いている間は時間が止まる」という思い込み。
NetHack では装備の付け外しも出し入れも 1 回ごとにターンが進み、敵が動く。ここは隠さず見せる。

- ドラッグ中、落とし先に所要ターンのバッジを出す（「3 ターン」）。0 ターンの操作は出さない。
- 時間を使う操作を実行しても画面は開いたまま（決定）。画面上端に「ターン経過」の短い表示を出す。
- 視界に敵対的なモンスターがいるときは、時間を使う操作の落とし先を警告色にする（知識フレームのモンスター一覧を使う。見えている相手だけ）。
- 長い操作（重鎧の着脱など）は本体の `afternmv` の途中で中断されうる。中断のメッセージはそのまま出し、画面は本体の状態をそのまま映す。

### 3.3 できない操作

画面は可否を判定しない。分かっている範囲で **見た目の示唆** だけ出す:
外套を着たまま鎧のマスに落とそうとしたら「外套を脱いでから着ます（合計 2 コマンド）」と出す、両手武器を持っていれば盾のマスを薄くする、など。
これらは公開されている状態（装備・既知の呪い）だけから決める。**未知の呪いを先回りして弾くことは絶対にしない**（呪いの漏れになる）。
送ってみて本体が断れば、本体のメッセージがそのまま出る。

### 3.4 入力装置

既存のインベントリと同じく、マウス・タッチ・パッド・Quest で同じ操作ができるようにする。

- パッド: グリッドと部位をフォーカス移動。A で「持ち上げ」→ 移動 → A で「置く」（ドラッグの代わり）。X でコンテキストメニュー
- タッチ: 長押しで持ち上げ、離して置く。短いタップはツールチップ
- Quest: パネルを手前に浮かべ、レイで同じ操作

### 3.5 装備セット

魔法を使うときと肉弾戦のときで装備を切り替える、といった「一式の切り替え」をワンボタンでできるようにする。

**登録**: 今の装備を名前つきで保存する（「魔法」「近接」など。数は 4〜6 程度）。部位ごとに「この物」「空ける（外す）」「気にしない（触らない）」のどれかを持つ。
物は持ち物の文字ではなく `o_id` で覚える（文字は `#adjust` や落として拾い直すと変わる）。
`o_id` は正体を表さない通し番号なので出してよい。保存先はセーブデータ側（本体）に置き、セーブ・再開・別の端末で同じセットが使えるようにする。

**切り替え**: 今の装備とセットの差分を取り、本体の新しいコマンド（`#nh3d_equipset`）に渡す。本体が次の順で実行する:

1. 外す: 外側から順（外套 → 鎧 → 肌着、手袋 → 指輪 など）。`A`（まとめて外す）と同じ `takeoff` の仕組み（`takeoff_order`）をそのまま使う
2. 持ち替え: 武器・予備・矢筒（`x` で済むなら `x` を使う）
3. 着ける: 内側から順（肌着 → 鎧 → 外套、指輪 → 手袋）

- 本体の普通の行動として、1 手順ずつターンを使う。合計の所要ターンは、ボタンのツールチップと確認の表示に出す。
- 途中で敵が現れる・攻撃される・呪われていて外せないなどで止まったら、そこで止める（本体の occupation の中断と同じ）。
  画面は止まった時点の装備を映し、「セットの途中で止まりました（残り: 外套を着る）」と出す。もう一度押すと残りを続ける。
- セットの物が持ち物にない（落とした・袋の中）ときは、その部位を飛ばして知らせる。袋の中なら「袋から出して装備」を選べる（＋1 ターン）。
- 呪いは先回りして判定しない（3.3 と同じ）。外せなければ本体のメッセージが出て、そこで止まる。

**呼び出し**: インベントリ画面の部位パネルの上にセットのタブ。画面を開かずに使えるよう、ホットキー（1 つずつ割り当て）とパッドのクイックメニューにも置く。

## 4. 重量

### 4.1 決定: 持っている物の本当の重量を出す

所持品の総重量は本当の値を出す（2026-11-18 決定）。

重量は物の正体の手がかりになる（灰色の石のうち負荷の石だけ 500、ランダムな見た目の兜・靴で重さが違う、魔法の袋は中身が軽くなる）。
それでも出すのは、**持っている物の重量はバニラでも負荷の段階の変化から分かる情報で、表示が具体的になるだけ** だから。

- 負荷の石は拾って総重量が 500 増えれば、それで識別できてよい。負荷の石の本質は「呪われていて捨てられない」ことのほうにある。
- 魔法の袋に物を入れて重量が減るのも、従来の UI で負荷の段階が変わって判別できたことと同じ。
- 持ち物の整理がしやすくなる利点のほうが大きい。

[player-knowledge-interface.md](player-knowledge-interface.md) 1 章の「知りうる」の境界との関係: 持っている物の重量は「持ってみれば分かる」ので知りうる側に入れる。
**まだ持っていない物（床・コンテナの中で、主人公が持っていない状態の物）の重量は出さない**。拾う前に正体が分かってしまうため。

### 4.2 表示

```
⚖ 412 / 450 （次: 重荷）   ▮▮▮▮▮▮▮▯   余裕 38
```

- 総重量: `inv_weight() + weight_cap()`（金貨は本体と同じく 100 枚で 1）。岩を投げられる姿のときの岩の扱いなども本体の計算のまま。
- 次の境目: 段階 n の上限は `wc + n × wc/2`（`calc_capacity()` の式）。今の段階と次の段階の名前（重荷・圧迫…）を添える。
- `wc`（`weight_cap()`）と総重量は C 側で出す。JS で式を再現すると、変化・浮遊・足の怪我・乗騎などの条件がずれる。
- 物ごとの重量: 持っている物はツールチップに出す（総重量の差で分かる値なので同じ扱い）。コンテナは中身込みの重量（`owt`）。
  グリッドのマスには出さない（設定で出せるようにしてもよい）。
- 重量管理の補助: ドラッグ中に、落とした場合・コンテナから出した場合の総重量と段階を棒に予告表示する。重い順の並べ替え表示（文字は変えない）。

足元・コンテナの区画で持っていない物を持ち物に移す予定（5.2）を作ったときは、予告に重量を足せない。
棒には「＋?」とだけ出し、決定して本体が拾った後に本当の値になる。

## 5. コンテナ

### 5.1 本体の動き（守ること）

- 出し入れは `use_container()` の 1 回で 1 ターン。1 回の中で「出す」と「入れる」をまとめてできる（`b`：両方）。
- 中身は `cknown` のときだけ分かる。開けたことのない袋の中身は分からない。施錠は `lknown` のときだけ分かる。
- 入れ子のコンテナは **直接は開けられない**。中の袋を使うには、いったん外に出す必要がある。
- 魔法の袋に魔法の袋・取消しの杖・袋つきの魔法の袋を入れると爆発する（`mbag_explodes`）。呪われた魔法の袋は開けるたびに中身が消える（`boh_loss`）。
- 床の箱は重くて持てないことが多い。足元のコンテナは `#loot`。
- 店の中では出し入れが売買になりうる（`sellobj_state`）。

### 5.2 画面での扱い: 「開いている間の操作をまとめて 1 回で送る」

ドラッグ 1 回ごとに `use_container` を呼ぶと、10 個入れるのに 10 ターンかかり、バニラ（メニューで 10 個選んで 1 ターン）より悪くなる。
そこで、コンテナの区画を **取引（トランザクション）** として扱う。

1. コンテナをクリック（グリッドの袋、足元の箱）すると区画が開く。この時点では本体には何も送らず、既知の中身（`cknown` なら）を表示する。
   中身を知らないコンテナは「?」の区画で、開ける操作が最初の 1 ターンになる。
2. 区画とグリッドの間でドラッグすると、移動は **予定** として表示される（半透明・矢印）。重量棒も予定を反映する。
3. 「決定」（または区画を閉じる・別のコンテナを開く）で、予定をまとめて 1 回の `use_container` として送る。出す物と入れる物の両方があれば「両方」で 1 回。
4. 結果は本体のメッセージと、更新された持ち物で表示する。予定どおりにならなかった物（呪いで出せない、爆発…）は本体の結果が正。

決定の前に本体の判断が要るもの（爆発・店の売買の確認）は、本体のプロンプトがそのまま出る。
画面が「爆発しますよ」と止めるのは、**両方の袋を魔法の袋と知っているときだけ**（知っている物の組み合わせなら警告してよい。知らない物では警告しない）。

### 5.3 入れ子

```
袋 (p)
├─ 薬 ×3
├─ 巻物 ×2
└─ 袋        ← 中身を知っていれば折りたたみで表示（読み取り専用）
   └─ 宝石 ×5
```

- 中のコンテナは、`cknown` なら中身を **読み取り専用** で表示する（前に見た内容。「最後に見たとき」の注記つき）。
- 中のコンテナに物を入れたい／中から出したいときは、画面が手順を組み立てて提示する:
  「外の袋から中の袋を出す → 中の袋に入れる → 中の袋を外の袋に戻す（3 ターン）」。実行するかは確認する。
  手順は普通のコマンドの列で、途中で割り込まれたらそこで止まる（本体の状態がそのまま正）。
- 入れ子の深さに制限は設けない（本体にもない）が、表示は 3 段まで展開し、それより深いものは「…」で畳む。

### 5.4 足元・床のコンテナ

足元の区画は、主人公のいるマスの物の一覧（`look_here` で見える範囲）と床のコンテナ。
床の箱は 5.2 と同じ取引の区画になり、`#loot` で 1 回。施錠されていれば開かず、本体のメッセージが出る（`#force` はコンテキストメニューに）。
隣のマスのコンテナは扱わない（本体も扱わない）。

## 6. 本体との接続

### 6.1 持ち物の構造化（知識インターフェースの K4）

今の持ち物は、`i` のメニューの文字列とグリフから組み立てている（`menuCapture.handleShimUpdateInventory`）。
この画面には構造化した値が要るので、[player-knowledge-interface.md](player-knowledge-interface.md) 4.6 で後回しにした「持ち物の構造化」を作る。

- 書き出しの時機: `update_inventory()`（`shim_update_inventory`）と、持ち物が変わる区切り。知識フレームとは別の区分 `inventory`。
- 1 件ごと: 文字、見た目のタイル（`nh3d_appearance_tile`）、数量、`owornmask`、`doname` の文字列、
  知っている場合だけ: BUC・強化値・充填数・防錆、それと腐食の段階・未払い・値段・灯り・名前の有無、重量（持っている物だけ。4 章）。
- コンテナ: `lknown`/`olocked`（知っていれば）、`cknown` のとき中身を同じ形で再帰的に。
- 主人公: 総重量、`wc`（負荷の境目の計算に使う）、現在の段階。
- 足元: 主人公のマスの物（見えている／触って分かる範囲）。
- 漏れの規則は K3 と同じく C 側の 1 か所（`nh3d_knowledge.c`）にまとめる。`otyp` は出さない。

### 6.2 操作の送り方

| 段階 | 方式 |
| --- | --- |
| 単発の操作（着る・外す・持つ・`#adjust`・落とす・拾う） | 今のコンテキストメニューと同じく、コマンドのキーと持ち物の文字を送る。既存の仕組みで足りる |
| コンテナの取引 | 隠しの拡張コマンド `#nh3d_loot` を本体に足し、「このコンテナから出す物の一覧・入れる物の一覧」を受け取って、`out_container`/`in_container` を本体の流れで呼ぶ（キー送りは `use_container` のプロンプトの分岐が多く壊れやすいので採らない）。ターン・メッセージ・爆発・店の処理は本体のまま |
| 装備セット | 本体に `#nh3d_equipset` を足す（3.5）。外す側は `takeoff` の仕組みをそのまま使い、着ける側も同じく occupation として 1 手順ずつ進める。中断も本体の扱いのまま |
| 手順の列（入れ子・装備の差し替え） | 単発の操作を順に送る。各手順の後に持ち物の更新を待ち、メッセージで割り込み・失敗を検出したら止める。手順が込み入って壊れやすいものは、コンテナや装備セットと同じく本体のコマンドに移す |

方針: 画面の操作を無理なく処理できないものは、キー送りで頑張らず本体にコマンドを足す（2026-11-18 決定）。
本体の変更はコマンドの入口だけで、可否の判定には手を入れない。

### 形式（版 1）

```json
{ "v": 1, "weight": 412, "capacity": 450, "encumbrance": 0,
  "twoweapon": false, "punished": false,
  "objects": [ { "id": 12, "letter": "a", "name": "...", "class": 1,
                 "glyph": 3500, "tile": 840, "quan": 1, "weight": 40, "worn": 256,
                 "buc": "uncursed", "enchantment": 1,
                 "eroded": { "level": 1, "kind": "rust" } } ] }
```

- 持ち物の一番上の物だけ: `letter`, `weight`（中身込みの `owt`。金貨は 100 枚で 1）, `worn`（`owornmask`）, `donning` / `doffing` / `skin`。
- 知っているときだけ現れる項目: `buc`, `enchantment`, `charges` / `recharged`, `erodeproof`, `container.locked`, `container.contents`。
  条件は `doname_base()` と同じ分岐にそろえた（強化値は武器・防具・武器の道具、指輪は種類に強化値があるとき、充填数は杖と充填のある道具）。
- 腐食: `eroded`（`rust` / `crack` / `burn`）, `eroded2`（`corrode` / `rot`）。名前に腐食の語がつく分類だけ。
- そのほか: `poisoned`, `greased`, `lit`, `unpaid`, `named`。
- `container`: コンテナに見える物すべて（正体を知らない魔法の小箱 = bag of tricks も袋と同じく含める）。
  中身は `cknown` のときだけ同じ形で入れ子になる（深さ 4 まで。それより深いと `contents: null, deep: true`。1 つのコンテナにつき 200 件まで、残りは `more`）。
- `capacity` は `weight_cap()`、`encumbrance` は `near_capacity()`、`weight` は `inv_weight() + weight_cap()`。
